# 0.4 Breaking Migration

Version 0.4 separates provider identity ownership from user profiles and makes
OAuth account changes explicit. It also replaces method-specific login hooks
with one typed authentication lifecycle for managed OAuth, magic-link, and
passkey flows.

## 1. Add the OAuth identity capability

OAuth providers now require both `adapters.user` and
`adapters.oauthIdentity`. Built-in memory and PostgreSQL bundles expose both;
`drizzleAdapter()` exposes `oauthIdentity` when `oauthAccounts` exists.

Custom adapters implement the focused port:

```ts
interface OAuthIdentityAdapter {
	getIdentity(provider: string, subject: string): Promise<OAuthIdentity | null>
	listIdentities(userId: string): Promise<OAuthIdentity[]>
	linkIdentity(identity: OAuthIdentity): Promise<void>
	unlinkIdentity(userId: string, provider: string): Promise<void>
}
```

Remove `getUserByProviderId` and `linkOAuthAccount` from custom `UserAdapter`
implementations. Existing D1/Drizzle `providerAccountId` column mappings do not
need to be renamed.

Add a database unique constraint for `(user_id, provider)` while retaining the
unique `(provider, provider_account_id)` owner constraint.

## 2. Replace `onLogin` with `onAuthentication`

```ts
hooks: {
	onAuthentication: async ({ event, method, user }) => {
		if (user) return { userId: user.id }
		if (method.kind === 'oauth' && method.intent === 'sign-in') {
			return { redirectTo: '/finish-signup' }
		}
	}
}
```

The former global `hooks.onLogin`, `magicLink.hooks.onLogin`, and
`webauthn.hooks.onLogin` options are removed. Magic-link lifecycle input
includes the verified email, passkey input includes the verified credential and
owner IDs, and OAuth input includes intent, provider, profile, and tokens.

An unknown OAuth identity no longer creates a user or matches an account by
email. The application must return an existing/new user ID after applying its
own collision and onboarding policy, or return a safe pending route.
Before returning a pending route, persist a bounded, short-lived, single-use
onboarding record bound to the browser session; Auth does not retain tokens or
create identity ownership for unresolved principals.

## 3. Use canonical OAuth routes

Replace legacy provider-shaped URLs with:

```text
GET  /auth/signin/:provider
GET  /auth/link/:provider
GET  /auth/reauth/:provider
GET|POST /auth/callback/:provider
POST /auth/signout
```

The `/auth/:provider`, `/auth/:provider/callback`, and `/auth/logout` aliases
are removed. `createAuthClient()` produces the canonical URLs; pass its
`basePath` option when `GoobitsAuth` is mounted outside `/auth`.
Custom mount paths must be absolute paths such as `/account/auth`; relative,
protocol-relative, and dot-segment paths are rejected.

## 4. Configure identity changes

Provider linking and unlinking require `oauth.authorizeIdentityChange`.
Authorize against recent primary authentication, not mere session presence.
Refuse an unlink when it would remove the account's last usable sign-in method.
The management client uses `listOAuthIdentities()` and
`unlinkOAuthIdentity(provider)`; stable provider subjects are never returned to
the browser.

Every custom `OAuthProvider` must implement `revokeTokens(tokens)`. Unlinking
revokes retained provider credentials before deleting local tokens and identity
ownership. A revocation failure leaves the local connection intact for retry.

## 5. Update provider and passkey setup

- Google identity uses the OIDC UserInfo `sub` claim and requires the
  `openid`, `profile`, and `email` identity scopes.
- Apple ID tokens require a nonce-bound, issuer/audience/time-validated RS256
  signature from a bounded cached JWKS; the `email` scope is required and
  `name` is optional.
- `AppleProvider.verifyServerNotification()` verifies and normalizes signed
  Apple account-change events; applications own durable replay protection,
  ordering, and account policy.
- Refresh responses preserve an existing refresh token when a provider omits a
  replacement.
- Conditional passkey autofill is available through
  `supportsConditionalPasskeys()` and
  `loginWithPasskey({ conditional: true, signal })`.

Run the package typecheck and tests after updating custom providers, adapters,
hooks, routes, and database constraints.
